# 实战 I/O 示例测试文档（2026-02-08）

## 0. 汇总

### 0.1 总体结论

- 测试范围：`agent/docs` 下 4 个章节中的全部 `[实战 I/O 示例]`，共 13 个示例。
- 测试结果：`成功 5`、`部分成功 4`、`失败 4`。
- 核心结论：
1. `NL2SQL` 安全机制（只读限制、LIMIT 收敛、缓存提速）整体可用。
2. `RAG` 索引/检索主链路可用，但文档示例与当前知识库内容不一致。
3. `A2A supervisor` 主链路当前不可用（关键 prompt 模板格式化错误）。
4. 语义记忆写入 Neo4j 存在类型错误（map 不能直接作为属性值），导致“写入后召回”目标失败。
5. 图谱子代理可以执行，但生成的关系类型与当前图谱真实关系存在偏差，导致结果为空。

### 0.2 分级汇总

| 等级 | 问题数 | 说明 |
|---|---:|---|
| P0 | 2 | 直接阻断核心链路：A2A supervisor 不可用；语义记忆写入失败 |
| P1 | 3 | 影响目标效果：Todo 拆分不符合预期；图查询关系错配；冷启动易超时 |
| P2 | 3 | 质量和一致性：公司实体检索不准；RAG 增量重复入库；文档示例路径与仓库不一致 |

### 0.3 本轮建议优先级

1. 先修 P0：恢复可用性（A2A 路由 + 语义记忆写入）。
2. 再修 P1：恢复目标效果（Todo 拆分、图谱关系查询、超时策略）。
3. 最后修 P2：提高精度与可维护性（NL2SQL 实体匹配、RAG 去重、文档同步）。

## 4. 根因与修改设计（按优先级）

### P0-1：A2A supervisor 路由失败（`'\n  "plan"'`）

**根因**
- `SUBAGENT_ROUTER_PROMPT` 包含 JSON 示例，但字面花括号未完全转义；
- `.format(agent_list=..., max_turns=...)` 时把 JSON 字段误当模板变量，触发异常；
- 异常发生在 `agent/subagents/router.py:33` 的 `format` 阶段，导致 supervisor 无法开始。

**修改方式（建议直接改）**

1. 在 `agent/core/prompts.py` 中，把 JSON 示例的字面花括号替换为 `{{` 和 `}}`。
2. 保留真正占位符仅两处：`{agent_list}` 和 `{max_turns}`。
3. 给 `SubAgentRouter.decide` 增加 prompt 构建保护，避免格式化异常直接中断。

**示例修正（节选）**

```python
SUBAGENT_ROUTER_PROMPT = """...
输出格式示例：
{{
  "plan": [
    {{
      "agent": "sql_facts",
      "objective": "...",
      "constraints": {{"tables": ["ip_bgp_entity"]}},
      "expected_output": "结构化结果",
      "budget": {{"max_tokens": 1200, "max_time_ms": 15000}}
    }}
  ],
  "reason": "为什么这样路由",
  "max_turns": {max_turns}
}}
"""
```

**验证标准**
- `A2A supervisor` 对任意简单任务应返回 `status=ok`，不再出现 `'\n  "plan"'`。

### P0-2：语义记忆写入 Neo4j 失败

**根因**
- `agent/memory/semantic.py:80-87` 直接 `SET c.metadata = $metadata`；
- Neo4j 属性不支持 map 类型，导致 `TypeError`。

**修改方式（建议直接改）**

1. 写入改为“可原生存储类型”：
   - `c.source`、`c.category`、`c.importance`、`c.tags`；
   - `c.metadata_json` 存完整 JSON 字符串。
2. 读取 `search` 时将 `metadata_json` 反序列化成 dict。
3. `FusionAgent._write_semantic_records` 不要吞异常，改为记录日志并继续处理后续记录。

**验证标准**
- 抽取记录后可写入、可按关键词召回，并返回 metadata 信息。

### P1-1：Todo 拆分不符合预期

- 实际模型常返回 `{"subtasks":[...]}`，被当成非法结构后降级为单条兜底任务。

   - 依次读取 `subtasks/items/todos/plan`。
2. 更新 `TODO_PLANNER_PROMPT`，强约束输出纯数组。

**建议代码片段**

```python
data = json.loads(response)
if isinstance(data, dict):
    data = data.get("subtasks") or data.get("items") or data.get("todos") or data.get("plan") or []
if not isinstance(data, list):
    data = []
```

**验证标准**
- 对复杂问题输出 3-6 条 Todo，且包含 `title + intent`。

### P1-2：graph_relations 关系类型错配

**根因**
- 当前生成 Cypher 常出现 `PEERS_WITH|UPSTREAM_OF`，与当前图谱实际关系定义不一致；
- 图谱真实关系已在导入器定义（如 `V4_UPSTREAM` 等）。

**修改方式**

1. 更新 `SUBAGENT_GRAPH_PROMPT` 的关系清单，明确真实可用关系。
