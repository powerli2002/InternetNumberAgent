# 文档治理规范

## 目标

文档治理的目标不是“把文档存起来”，而是保证任何时刻都能快速回答：
- 当前系统是什么。
- 当前实现和运行方式是什么。
- 哪份文档是权威的。

## 当前规则

### 1. 单一权威
- 一个主题只允许一份当前权威文档。
- 如果已有权威文档，优先修改它，而不是新建平行文件。

### 2. 直接改正文
- 禁止以“新增一节更新记录”“补充说明”“临时修复说明”的方式做增量维护。
- 每次修改都应直接重写正文，使整篇文档在修改后仍然完整、最新、自洽。

### 3. 过期文档清理
- 发现过期文档时，必须在当前任务中完成以下动作之一：
  - 更新为当前内容
  - 归档到 `docs/90-archive/`
  - 直接删除

### 4. 历史内容退出主文档区
- 历史方案、旧面试材料、实验记录、私人环境笔记，不放在当前文档区。
- 需要保留时，统一移动到 `docs/90-archive/`，并默认视为非权威。

### 5. 重大改动同步规则
以下变更必须同步检查文档：
- 数据模型、表结构、字段语义、导入逻辑
- LangGraph 编排、MCP 工具、记忆、上下文工程
- 部署方式、端口、配置项、数据卷
- 重要脚本入口与运行流程

### 6. 命令变更强制同步
- 只要代码修改影响命令、入口脚本、默认解释器、默认配置加载方式或运行前置条件，必须在同次任务同步修改对应权威文档。
- 禁止出现“代码已经改了，但 README 或运行文档里的命令仍是旧的”状态。
- 提交最终结果前，至少核对一遍根 `README.md` 与对应主题的 `docs/04-operations/*.md` 是否仍可按当前代码执行。

## 推荐巡检频率
- 日常：每次功能开发或修复都顺手清理相关文档。
- 周期：建议每 2 周或每月做一次文档巡检。

## 巡检清单
- 当前文档是否仍指向真实代码路径。
- 当前命令、端口、配置项是否还能执行。
- 是否存在多个文档同时描述同一主题。
- 是否有历史方案仍混在主文档区。
- `docs/README.md` 的导航是否仍然成立。

## 本仓库的文档分层
- `01-overview`：系统理解入口
- `02-architecture`：当前实现和技术链路
- `03-data`：数据模型与约束
- `04-operations`：部署、监控、排障、接入
- `05-ai`：AI 规则、Harness、文档治理
- `90-archive`：历史归档
