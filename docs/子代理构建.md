# 子代理构建方案（fusionprocessing，FastMCP + A2A 版）

本文档描述当前仓库已落地的子代理方案：  
**主代理编排（FusionAgent） + 工具层 FastMCP + 代理间 A2A（HTTP+SSE） + 全链路 LangSmith**。

---

## 1. 设计目标

- 子代理触发不依赖硬编码规则，由 Function Calling 输出结构化路由。
- 工具调用不走本地函数直调，统一走 MCP 协议。
- 代理协同不走进程内私有对象，统一走 A2A 协议。
- 运行链路可观测，trace_id 在 API → A2A → MCP 全链路透传。

---

## 2. 当前实现总览

### 2.1 主流程

1) `FusionAgent` 产出 `ToolRouterDecision`（`route_tools`）。  
2) 常规步骤（`nl2sql/rag`）调用 `MCPToolClient` 访问 FastMCP 工具服务。  
3) 复杂步骤（`todo`）拆分 TodoItem，通过 `A2AClient` 提交到 `supervisor` worker。  
4) `supervisor` worker 生成 `RouterDecision`，调用 `sql_facts/rag_docs/graph_relations/verifier` 子代理。  
5) 子代理只通过 MCP 调工具，返回统一 `A2AResultEnvelope`。  

### 2.2 代码落点

- 主代理：`agent/runtime/fusion_agent.py`
- MCP 服务：`agent/services/mcp/server.py`
- MCP 客户端：`agent/services/mcp/client.py`
- A2A 协议：`agent/services/a2a/models.py`
- A2A 客户端：`agent/services/a2a/client.py`
- A2A worker 服务：`agent/services/a2a/server.py`
- A2A 执行器：`agent/services/a2a/executor.py`

## 3. 协议定义（已落地）

### 3.1 A2A 输入协议：`A2ATaskPayload`

```json
{
  "task_id": "uuid",
  "agent": "supervisor",
  "objective": "任务目标",
  "constraints": {
    "tables": ["ip_bgp_entity", "as_entity"],
    "tools_allowed": ["sql_facts", "rag_docs", "graph_relations", "verifier"]
  },
  "context": {
    "question": "用户问题",
    "task_id": "todo-1"
  },
  "expected_output": "结构化结果 + 证据摘要",
  "budget": {"max_tokens": 1200, "max_time_ms": 15000},
  "trace_id": "trace-xxx"
}
```

### 3.2 A2A 输出协议：`A2AResultEnvelope`

```json
{
  "status": "ok",
  "agent": "sql_facts",
  "trace_id": "trace-xxx",
  "result": {"sql": "SELECT ...", "result": {"row_count": 10}},
  "evidence": [{"source": "nl2sql", "content": "SQL: ..."}],
  "errors": [],
  "metrics": {"elapsed_ms": 320}
}
```

### 3.3 A2A 事件协议（SSE）

`accepted / started / progress / completed / failed / heartbeat`

```text
event: completed
data: {"event_type":"completed","task_id":"...","status":"completed","data":{"result":{...}}}
```

## 4. 子代理划分（3+1）

- `sql_facts`：结构化事实查询（MCP: `nl2sql_query`）
- `rag_docs`：文档证据检索（MCP: `rag_search`）
- `graph_relations`：图谱关系查询（MCP: `neo4j_query`，Cypher 由 LLM 生成）
- `verifier`：冲突核验（LLM 对多源结果做一致性判断）
- `supervisor`：路由与结果聚合（内部使用 RouterDecision）

---

## 5. FastMCP 工具层（已落地）

MCP 服务统一暴露以下工具：

- `health`
- `nl2sql_query`
- `rag_search`
- `neo4j_query`
- `note_search`
- `todo_add`
- `todo_list`

每个工具均：
- 使用结构化入参/出参；
- 在服务端写 LangSmith run（`mcp_server:<tool>`）；
- 保留底层工具安全守卫（SQLGuard/CypherGuard）。

---

## 6. LangSmith 监控策略（全链路）

### 6.1 追踪节点

- API 主链路：`fusion_agent`
- 主代理路由：`tool_router`
- MCP 客户端调用：`mcp_tool:<name>`
- MCP 服务端工具：`mcp_server:<name>`
- A2A 客户端调用：`a2a_submit_task` / `a2a_stream_events` / `a2a_execute_task`
- A2A Worker：`a2a_task_execute` / `a2a_worker:<agent>`
- Worker 内部路由：`subagent_router`

### 6.2 关键 metadata

- `trace_id`
- `question_type`
- `agent`
- `tool`

---

## 8. 为什么采用 FastMCP + A2A

- 工具标准化：跨服务、跨语言复用能力更强。
- 代理解耦：主代理与子代理职责边界清晰，易扩容和隔离故障。
- 可观测性提升：协议边界天然可埋点，排障更直接。
- 演进成本更低：后续新增工具/代理不需要侵入主代理核心逻辑。
