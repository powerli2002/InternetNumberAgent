# 故障排查与防护

## PostgreSQL 数据卷防护
- `docker/docker-compose.yml` 中 PostgreSQL 挂载路径必须使用 `../mount/...`。
- 如果 compose 文件位置变化后仍使用 `./mount/...`，很容易把数据挂到错误目录，触发空目录初始化或数据损坏。
- 迁移或重命名数据目录前必须先停容器。

## 常见问题

### 1. PostgreSQL 启动失败
排查方向：
- 检查 `mount/pgdata` 是否存在 `PG_VERSION`、`base/`、`global/`、`pg_wal/`。
- 检查 compose 文件中的挂载路径是否仍指向项目根目录下的 `mount/pgdata`。
- 检查容器是否在数据目录迁移时仍处于运行状态。

### 2. 导入后表结构不一致
排查方向：
- 确认先执行统一 DDL，再导入 CSV。
- 确认导入使用的是当前快照日期而不是旧日期残留文件。
- 确认没有自行新增 `_audit` 或原始镜像表污染查询范围。

### 3. NL2SQL 结果异常
排查方向：
- 检查 `ALLOWED_TABLES` 是否包含目标表。
- 检查字段名是否与规范化后的列名一致。
- 检查 SQL 是否被 `SQLGuard` 收敛或拒绝。

### 4. RAG 检索不到文档
排查方向：
- 确认向量索引已构建到正确的 collection。
- 确认入库路径和查询 collection 配置一致。
- 检查文档源路径是否已经迁移或被归档。

### 5. Neo4j 查询为空
排查方向：
- 确认图谱已导入。
- 确认问题是否真的应走图关系，而不是结构化查询。
- 确认当前图谱实体与关系是否和导入脚本一致。

## 预防规则
- 修改部署、路径、端口、表结构时，同步更新 `docs/04-operations/` 与 `docs/03-data/`。
- 避免在文档中保留失效的主机地址、密码、私人环境信息。
- 每次修文档时应整篇复核，不要追加零散“更新说明”。
