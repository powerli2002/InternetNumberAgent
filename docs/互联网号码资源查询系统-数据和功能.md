Inferred AS to Organization Mapping Dataset 是 CAIDA 使用注册信息推断的从 AS 自治域到运营的机构的映射。

2）AS 商业关系数据

AS Relationships 是 CAIDA 提供的关于 AS 自治域关系的数据集，CAIDA 提供了两种 AS Relationships 数据集，serial-1 和 serial-2 数据集，其中 serial-1 数据集由论文“AS Relationships, Customer Cones, and Validation”中的方法获取，serial-2 数据集由“Inferring Multilateral Peering”中描述的方法再补充上 serial-1 数据集而得。AS 自治域的关系主要包括了 Peer to Peer 关系和 Provider to Custmer 关系。

3）AS 类型数据

AS 类型数据是 CAIDA 提供的关于 AS 自治域分类的数据，包括是否是 Content、ACCESS 网络、以及 Transit 网络。

4）AS Rank 数据

AS 遵守典型的自愿双边互连（“对等”）协议，以便为 Internet 的某些子集提供彼此的可达性，并对网络的运营、研究和演进产生影响。Internet 拓扑、路由、工作负载和性能的现实模型必须考虑潜在的经济动态。尽管网络之间的大多数互连（“对等”）协议都是秘密的，但可以从 traceroute 派生和 BGP 派生的 Internet 拓扑数据集推断出在 IP、路由器和 AS 粒度上的一些信息（有关经济建模的更多详细信息，请参阅关于互联网传输和对等互连经济学的研究）。

AS rank 使用这些数据集，根据 AS 在全局路由系统中的影响度量来估计自治系统的宏观排名，特别是基于 AS 之间推断的业务关系确定其 customer cone 的大小。下面将更详细地解释这些概念。

AS 的 rank 基于其 customer cone 的大小，而 customer cone 大小又是由 CAIDA 的 AS 关系推理算法从 BGP 路径中推断出来的。AS rank 指的是具有更大 customer cone 或 degree 的 AS 的排名。因此，具有同样大的 customer cone 大小和 degree 的 AS 将具有相同的 rank。

## DNSdata

**DNS 日志数据采集模块**

DNS，即域名解析系统，是重要的互联网资源导航系统。用户访问的域名后，经过 DNS 的调度和解析，将用户流量引导到合适的资源节点。
用户发起 DNS 请求后，递归服务器会迭代权威服务器返回的应答，直到查询到域名最终解析结果的 IP 地址。**权威服务器**则只会应答在服务器中注册的域名，并根据 DNS 请求的来源地址，即向其发起请求的递归服务器的地址，来确定用户的网络拓扑，返回适当的解析结果。由 DNS 服务器负责完成，在此过程中 DNS 服务器会进行以下解析记录的添加：A 记录、AAAA 记录、PTR 记录、CNAME 记录、MX 记录、NS 记录、TXT 记录、SRV 记录和 URL 记录。

权威 DNS 服务器是域名系统中真正“知道”某个域名对应 IP 地址的服务器。它是域名解析链中的最后一环，**权威服务器可能有多个**，

课题定时读取 DNS 解析日志，提取日志中域名到 IP 地址的映射（A 记录、AAAA 记录)，获取域名列表和对应的解析 IP 地址。

| 记录类型    | 作用                                         |
| ------- | ------------------------------------------ |
| A 记录     | 将主机名映射到 IPv4 地址                              |
| AAAA 记录  | 将主机名映射到 IPv6 地址                              |
| PTR 记录   | 反向解析记录，将 IP 地址映射回主机名                         |
| CNAME 记录 | 指定一个域名是另一个域名的别名                            |
| MX 记录    | 指示电子邮件服务器应该发送给哪个邮件服务器                      |
| NS 记录    | 指定哪些 DNS 服务器负责某个域或子域                         |
| TXT 记录   | 通常用来存放关于域的一些额外信息，比如验证域名所有权或者设置 SPF 记录以防止邮件欺骗 |
| SRV 记录   | 用于指定特定服务的位置，比如 SIP 协议的服务位置                   |
| URL 记录   | 虽然不是标准的 DNS 记录类型，但在某些实现中可能用作指向网页的别名          |

## BGPdata

边界网关协议简称 BGP(Border Gateway Protocal)，是一个去中心化自治路由协议。它通过维护 BGP 路由表来表示 AS 之间的可达性。

路由信息服务（Routing Information Service）是 RIPE 提供的一系列 BGP 数据服务，在全球网络运营商的帮助下，RIPE 的 RIS 使用了一组分布在全球各地的远程路由收集器（RRC）来收集和存储互联网 BGP 路由数。

Oregon 大学的 Route Views 项目是互联网用户获取实时 BGP 信息的一个工具，Route Views 从互联网上的多个不同的主干网，从不同的位置获取全球路由系统的实时 BGP 信息，和 RIPE RIS 非常相似，Route Views 也提供了多种不同的 BGP 信息的访问方式

###  **运营商路由快照采集模块**

主要目的为下载路由数据

![](assets/Pasted%20image%2020240718150041.png)
每个 VP（Vantage Point）会通过 BGP 协议与其对等体进行正常数据交互，通过使用其他对等体传入的 Adj-RIB-In 更新自己的 Loc-RIB，然后根据输出策略向其他对等体传送 Adj-RIB-Out 信息；一个收集器会与多个 VP 建立 BGP 会话链接，从而接收各 VP 发送的 Adj-RIB-Out 信息并解析汇总。

对于每个 VP，收集器都会维护一个会话状态和域间路由信息快照。收集器会对域间路由信息快照进行定期转储，频率分别为几小时和几分钟，前者称为 RIB 转储，其提供了对 BGP 域间路由表更新信息的有效总结；后者被称为更新转储，主要记录各 VP 的状态更改情况，更新转储携带大量需要处理的信息，但提供了可观察域间路由动态的完整视图，可用于近实时监控应用程序。

**RRC 实例（Routing Collector Instance）** 是指特定地理位置或网络交换点上部署的路由收集器。这些实例旨在收集和记录通过该位置的路由信息，包括路由表、路由更新和自治系统（AS）路径等数据。

RIPE 网络协调中心（RIPE NCC）的 Routing Information Service（RIS）项目就是一个典型的例子。RIS 使用多个 RRC 实例在全球范围内收集和分发路由数据。每个 RRC 实例有一个唯一的标识符，例如 rrc00、rrc01 等，代表不同的路由数据收集点。

inetnum/inetnum6 对象包含有关分配和分配 IPv4 地址和 IPv6 空间资源的信息，是互联网号码资源信息库的主要元素之一，其主要属性见表

inetnum 对象使用 mntner 对象进行保护，如果对象在对象中包含对 mntner 的引用，则对象受 mntner 保护。这是通过包含“mnt-by:”属性来完成的。其他“mnt-xxx:”属性提供分级保护。

“mnt-by:”属性在所有对象类型中都是强制性的。“mnt-lower:”、“mnt-routes:”和“mnt-domains:”属性都提供分层授权。当一个对象中包含多个值时，它们也适用于逻辑“或”。

person 对象提供有关真实人物的信息，以 admin-c 或者 tech-c 引入引用。最初的意图是，这应该只用于负责与信息库中注册的互联网资源相关的技术或管理问题的联系人。然而，许多资源拥有者使用的商业模式也是记录已分配资源的最终用户客户。其目的之一被定义为资源管理人员的联系人数据库。person 对象包括了技术人员或管理人员的详细信息，主要属性包括有 person、address、country 和 nic-hdl 等

在 `ASWithMailKey` 类中，分组的具体实现是通过 `grouped_csv` 方法来完成的。这个方法根据参数 `handle_as` 的不同取值（True 或 False），决定是处理 AS 信息还是 IP 地址信息。

6. 当 `handle_as=True` 时，方法会读取 AS 信息的 CSV 文件，过滤出状态为 'allocated' 或 'assigned' 的记录，并根据不同的 RIR（如 'arin'、'apnic' 等），读取相应的 RDAP 信息文件（如 'arin_as_rdap_info.csv'），然后根据 AS 号码（ASN）进行数据合并和处理。
   
7. 当 `handle_as=False` 时，方法会分别处理 IPv4 和 IPv6 地址信息，同样过滤出状态为 'allocated' 或 'assigned' 的记录，并将它们合并为一个 DataFrame。接着，根据不同的 RIR，读取相应的 IP 地址的 RDAP 信息文件（如 'arin_ip_rdap_info.csv'），然后根据 IP 前缀进行数据合并和处理。

在处理过程中，对每个 RIR 的数据进行组织机构、联系人信息的解析和补充，并通过 RDAP 中提供的信息，如注册者、管理者、技术支持和滥用联系人等，来丰富每条记录的信息。最终，将处理好的数据以字典的形式返回，其中键是各个 RIR 的名称，值是处理好的 DataFrame，包含丰富的联系信息和补充的邮箱信息。
