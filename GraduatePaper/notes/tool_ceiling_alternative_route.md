# 工具能力达到上限时的条件转向方案

> 日期：2026-06-08  
> 性质：基于 P0 实测结果的条件方案，不直接替换 GeoAgent-R1 当前主线  
> 推荐方向：基于 SFT 与 GRPO 的风险感知 IPv6 定位 Agent

## 一、结论

如果现有主动、被动定位工具已经没有可行优化空间，毕设不应继续把“Agent 选择工具后提升坐标精度”作为核心目标。P0 Oracle 已证明这个动作空间的定位增益过小：

- 929 个目标中，非 ModuGeo 工具仅在 48 个目标上更优，比例为 5.17%。
- Oracle Median 仅从 30.234 km 降至 30.022 km。
- Oracle Mean 仅从 61.169 km 降至 60.628 km。
- Oracle P90 保持 125.048 km 不变。
- rDNS 与被动 IPDB 当前全部不可用；主动定位虽有 565 个可用结果，但多数结果不能改善 ModuGeo。

因此，继续进行定位纠错型 GRPO 很可能收敛为“始终使用 ModuGeo”。这不是有价值的 Agent 策略。

推荐的条件转向是：

> **训练一个风险感知、可选择性输出的 IPv6 定位 Agent。Agent 不负责凭空产生更准坐标，而是判断基础定位结果是否可信，识别工具失效与证据冲突，选择输出粒度、拒答时机和最低成本的取证路径。**

该方向仍然以 LLM Agent、SFT 和 GRPO 为主，不退化为单纯训练定位模型。

建议论文题目：

> **基于监督微调与可验证强化学习的风险感知 IPv6 地理位置推断 Agent 研究**

## 二、为什么当前数据仍能支撑该方向

工具不能提供更准坐标，不等于数据没有可学习任务。当前 P0 环境仍提供以下监督信号：

1. **结果风险存在明显差异。** ModuGeo 的 Mean 为 61.169 km，明显高于 Median 30.234 km，说明存在需要识别的长尾错误。
2. **工具失败状态丰富且可自动验证。** rDNS、主动定位、被动 IPDB、WHOIS 已统一返回覆盖、失败原因、质量与成本。
3. **真值只在训练奖励和评测侧可见。** 当前环境已完成模型可见数据与私有真值隔离，可构造可验证奖励。
4. **前缀外评测已经建立。** 929 个目标按 `/48` 隔离为 train、validation、test 和 prefix-OOD，可评估风险判断是否泛化。
5. **多轮决策仍有意义。** Agent 可以学习何时检查工具、何时停止、何时降低输出粒度、何时拒答，而不是机械调用所有工具。

该方向的价值从“提高所有样本的坐标精度”改为：

- 降低高置信错误和错误融合。
- 在给定覆盖率下控制定位风险。
- 在工具缺失、低质量和冲突时维持稳健行为。
- 用更少调用成本得到可解释结论。

## 三、核心研究问题

主研究问题：

> 在 IPv6 定位工具覆盖不足且无法继续改善的条件下，经过 SFT 与 GRPO 训练的多轮 Agent，能否在未见前缀上识别高风险定位、诊断工具失败，并通过选择性输出与可信拒答降低错误信任？

子问题：

1. SFT 能否让 Agent 学会合法工具调用、失败诊断、证据解释和停止动作？
2. GRPO 能否联合优化风险、覆盖率、工具成本和错误信任率？
3. 多轮 Agent 是否优于规则、传统分类器和 Prompt-only Agent？
4. 在工具缺失、低质量、冲突和陈旧等扰动下，Agent 是否保持稳健？
5. Agent 能否在 prefix-OOD 上保持校准，而不是记忆 ASN 或运营商模式？

## 四、Agent 任务定义

### 4.1 输入与环境

Agent 可观察：

- 目标 IPv6 的无真值网络属性、ASN、运营商与前缀信息。
- ModuGeo 候选及其模型侧质量特征。
- 各工具的可用性、失败状态、质量特征、候选证据和调用成本。
- 当前已执行动作、剩余预算和证据冲突状态。

Agent 不可观察真实城市、真实经纬度以及由评测真值直接计算的特征。

### 4.2 动作空间

- `inspect(tool)`：检查工具适用性或结果质量。
- `query(tool)`：调用一个可用工具。
- `compare_evidence()`：比较候选与证据冲突。
- `finalize(level, confidence)`：按城市、省级或更粗粒度输出。
- `abstain(reason)`：证据不足时拒答。
- `stop()`：已有证据足够时停止，避免无效调用。

### 4.3 输出

```json
{
  "decision": "finalize | abstain",
  "location_level": "city | province | coarse | none",
  "candidate_source": "modugeo | active | other",
  "confidence": "high | medium | low",
  "risk_reason": "结构化原因",
  "evidence_ids": ["可回放证据标识"]
}
```

## 五、SFT 数据建设

SFT 的目标不是让模型记住位置，而是让模型学会交互协议和基础决策。教师轨迹应覆盖：

- ModuGeo 风险低，Agent 立即停止。
- ModuGeo 风险高，Agent 检查其他证据后降低粒度或拒答。
- 工具无覆盖，Agent 正确诊断并避免重复调用。
- 工具有输出但质量低，Agent 不错误融合。
- 多工具冲突，Agent 解释冲突并保守决策。
- 调用预算不足，Agent 选择最有价值动作。

真实 P0 回放负责提供基础轨迹。为了训练工具故障鲁棒性，可以在训练划分上加入**明确标注的受控故障注入**，例如缺失、低质量、冲突和陈旧状态。故障注入只能用于训练与鲁棒性实验，不能伪装成真实定位证据，也不能改变测试集真值。

当前 650 条 SFT seed 中真正选择非 ModuGeo 的轨迹过少，正式 SFT 前必须按失败类型、风险等级和输出动作做平衡采样。

## 六、GRPO 设计

GRPO 对同一个任务采样多条交互轨迹，使用隐藏真值和工具执行记录计算可验证奖励。建议奖励从定位改善改为选择性风险控制：

```text
R = R_selective_correctness
  + R_failure_diagnosis
  + R_supported_decision
  + R_calibration
  - R_false_trust
  - R_invalid_action
  - R_unnecessary_cost
  - R_repeated_failure
```

- `R_selective_correctness`：输出时误差与粒度匹配，拒答时确实属于高风险。
- `R_failure_diagnosis`：正确识别 `unavailable`、`coverage_miss`、`low_quality` 和 `conflict`。
- `R_supported_decision`：最终结论能够回溯到实际证据。
- `R_calibration`：置信度与真实风险一致。
- `R_false_trust`：对高误差结果给出高置信输出的强惩罚。
- `R_invalid_action`：非法动作和格式错误惩罚。
- `R_unnecessary_cost`：无收益工具调用惩罚。
- `R_repeated_failure`：重复调用已知失败工具的惩罚。

训练应采用课程顺序：格式与合法动作、失败诊断、停止与拒答、冲突处理、预算约束、多轮 GRPO。

## 七、评测与基线

核心指标：

- Risk-Coverage Curve 与 AURC。
- 50%、70%、80%、90% 覆盖率下的 Mean、Median 和 P90 error。
- 高风险样本召回率，例如误差大于 100 km 的识别率。
- False Trust Rate：高误差但高置信输出的比例。
- 正确拒答率、错误拒答率与输出粒度准确率。
- 工具失败诊断准确率、非法调用率、重复失败调用率。
- 平均工具调用次数、平均成本和平均轨迹长度。
- prefix-OOD 上述指标。

必须包含以下基线，否则无法证明 LLM Agent 的必要性：

- 固定使用 ModuGeo。
- 固定阈值和人工规则。
- 使用同样特征的 Logistic Regression、XGBoost 等传统风险分类器。
- Prompt-only Agent。
- SFT-only Agent。
- SFT + GRPO Agent。
- 使用隐藏真值排序的选择性 Oracle 上界。

如果传统分类器在风险识别和成本上全面优于 Agent，应如实收缩结论：LLM Agent 的价值只存在于多轮故障诊断与证据解释，而非单步风险分类。

## 八、其他可选方向与排序

| 排名 | 方向 | 可行性 | 与 LLM Agent/SFT/GRPO 匹配度 | 主要风险 |
| --- | --- | --- | --- | --- |
| 1 | 风险感知与选择性输出 Agent | 高 | 高 | 需证明优于简单规则和分类器 |
| 2 | 工具故障鲁棒性 Benchmark + Agent | 高 | 高 | 受控故障不能替代真实数据多样性 |
| 3 | 主动数据采集 Agent | 中 | 高 | 奖励延迟、实验成本和实现复杂度高 |
| 4 | 纯定位结果校准器或 Verifier | 高 | 中 | 容易退化为普通分类任务 |

主动数据采集 Agent 的任务是让 Agent 在预算内选择值得新增标注或探测的前缀，以最大化后续定位模型收益。该方向更有研究新颖性，但需要闭环重训与长期奖励，不建议作为当前时间受限条件下的首选。

## 九、转向门禁与执行路径

### 9.1 转向门禁

满足以下条件时，正式从定位纠错型 Agent 转为风险感知 Agent：

1. 工具适配实验完成后，非 ModuGeo Oracle 改善率仍低于 10%。
2. Oracle 对 Median 和 P90 的改善仍小于预设有意义阈值。
3. 新工具获取、主动探测扩容或被动库补全没有现实可行路径。

当前 P0 已满足第一项，并在现有工具条件下满足第二项；第三项需要由项目约束最终确认。

### 9.2 推荐 P1

1. 从私有真值生成风险标签和选择性评测器，但严格禁止写入 Agent 输入。
2. 建立固定规则与传统风险分类器基线。
3. 扩展 SFT seed，使失败类型、风险等级、停止和拒答动作平衡。
4. 增加受控故障注入与对应泄漏审计。
5. 先训练 SFT-only Agent，并在 prefix-OOD 上验证失败诊断和 Risk-Coverage。
6. 只有 SFT 策略优于 Prompt-only 且奖励存在组内方差时，再进入 GRPO。

## 十、研究边界

- 929 个目标足以完成原型和本科毕设实验，但不足以声称对互联网 IPv6 的广泛泛化。
- 故障注入能增加交互状态多样性，不能增加独立目标和真实网络分布多样性。
- Agent 无法创造不存在的定位证据，因此论文结论必须聚焦可信决策，而不是声称提升工具本身精度。
- GRPO 只是一种优化方法，创新点必须来自可验证环境、风险目标、故障建模和实证分析。

## 十一、相关方法依据

- DeepSeekMath 提出 GRPO，说明可使用组内相对奖励优化可验证结果任务：https://arxiv.org/abs/2402.03300
- Search-R1 展示了使用强化学习训练多轮工具交互策略的可行性：https://arxiv.org/abs/2503.09516
- ReTool 展示了 SFT 冷启动与结果奖励结合训练策略性工具使用的方法：https://arxiv.org/abs/2504.11536
- RAGEN 指出多轮 Agent RL 需要多样初始状态和更细粒度奖励，并存在策略退化风险：https://arxiv.org/abs/2504.20073
