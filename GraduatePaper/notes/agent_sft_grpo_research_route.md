# GeoAgent-R1：基于 SFT 与 GRPO 的 IPv6 地理位置推断 Agent 研究路线

> 调研日期：2026-06-07  
> 主题边界：以 LLM Agent 的训练与决策学习为主线，不从头训练领域大模型  
> 结论性质：后续研究路线建议，尚未替换 `DASHBOARD.md` 中的当前实验计划

## 一、方向定位

毕业设计的主要方向是：

> **构建一个可验证的 IPv6 地理位置推断交互环境，以 ModuGeo 和主动、被动定位工具作为证据来源，通过 SFT 冷启动与 GRPO 强化学习，训练 LLM Agent 学会按需取证、工具调度、结果融合、及时停止和可信拒答。**

推荐方法暂命名为 **GeoAgent-R1**，建议论文题目为：

> **基于监督微调与可验证强化学习的 IPv6 地理位置推断 Agent 研究与实现**

当前主动、被动 IPv6 工具无法很好作用于现有数据集，是实现这一主要方向必须解决的关键问题之一，但不是毕设的最终研究方向。工具适配工作的目标是为 Agent 构建有效、可训练的动作与观察环境。

本课题的核心研究对象包括：

1. 如何把 IPv6 定位建模为多轮、可交互、可自动验证的 Agent 任务。
2. 如何解决工具与数据集不匹配问题，为 Agent 提供具有差异化价值的工具结果。
3. 如何构造无标签泄漏的高质量轨迹，通过 SFT 教会 Agent 基础工具使用与决策。
4. 如何使用 GRPO，让 Agent 学会改善 ModuGeo 的尾部错误，同时控制工具成本和错误退化。

## 二、当前基础与主要阻塞

当前代码已经具备 Agent、工具、轨迹和奖励的基本外形，但还不能支撑有效的 SFT/GRPO 训练。

### 2.1 当前有效基础

- ModuGeo Median 误差为 31.8 km，覆盖率 100%，可作为稳定基础定位器。
- 已有目标真值、traceroute、probes、landmarks 和 ModuGeo 预测。
- 已实现 rDNS、主动定位、被动 IPDB、WHOIS/BGP、规则调度、Qwen 调度与离线奖励策略。
- 地理真值可以自动验证最终结果，天然适合结果奖励强化学习。

### 2.2 必须解决的关键问题

#### 问题 A：工具与数据集不匹配

| 工具 | 当前表现 | 问题 |
| --- | --- | --- |
| rDNS | 评测覆盖率 0%，PTR 命中约 1% | IPv6 PTR 稀疏，解析能力也需验证 |
| CBG 主动定位 | Median 678 km，覆盖率 59% | 只有 3 个 probes，约束不足 |
| 被动 IPDB | 覆盖率 0% | 缺少可用 IPv6 数据库 |
| WHOIS/BGP | 多为粗粒度注册信息 | 与实际使用位置可能偏离 |

如果该问题不解决，Agent 会退化为始终选择 ModuGeo，SFT 和 GRPO 都没有有效决策空间。

#### 问题 B：当前 Agent 不是真正的多轮 Agent

- `QwenToolUseScheduler` 只进行一次动作分类。
- 当前动作主要是 `stop/rdns/active/passive/all`。
- 工具执行后没有基于新观察继续决策的机制。

#### 问题 C：当前训练数据与 RL 实现不成立

- 当前 SFT 状态包含 `truth_region` 和 `truth_city`，存在标签泄漏。
- 当前轨迹基本为单步动作。
- 当前离线奖励策略只是按真值统计动作平均收益，并非实际强化学习训练。

## 三、核心研究问题

> 在主动与被动定位证据覆盖不足、质量不稳定的条件下，经过 SFT 与 GRPO 训练的 LLM Agent，能否学习工具适用性判断、多轮取证和动态停止，并以可控成本改善 ModuGeo 的定位结果？

子问题：

1. 如何构建适合 Agent 训练的 IPv6 定位多轮交互环境？
2. 如何适配当前主动、被动工具，使其在目标数据集上产生可用且互补的定位证据？
3. SFT 能否让 Agent 学会合法工具调用、证据读取和基础决策？
4. GRPO 能否让 Agent学会工具适用性判断、按需取证和动态停止？
5. 多轮 Agent 是否优于单步调度、固定全工具调用和规则策略？
6. Agent 的提升能否泛化到未见前缀、未见 ASN 和尾部困难样本？

## 四、总体架构

```text
目标 IPv6 与基础网络属性
  -> 多轮 LLM Agent
     -> 判断工具适用性
     -> 选择工具与参数
     -> 获取主动/被动定位证据
     -> 检查结果质量与冲突
     -> 继续取证、融合、停止或拒答
  -> 候选位置、置信度与证据链

训练阶段：
工具适配 -> Oracle 效用审计 -> 教师轨迹生成
         -> SFT 冷启动 -> 环境内多轨迹采样 -> GRPO
```

ModuGeo 是基础定位器，而不是 Agent 必须取代的模型。Agent 的价值是识别 ModuGeo 风险，并在存在可靠互补证据时进行修正。

## 五、关键问题模块：工具适配与效用恢复

该模块是构建有效 Agent 环境的必要前置工作，但服务于 SFT + GRPO Agent 主线。

### 5.1 统一工具状态

每次工具调用必须返回结构化状态：

```text
执行状态
候选位置
覆盖状态
质量特征
适用条件
失败原因
调用成本
```

失败状态至少区分：

- `input_missing`：缺少工具执行输入。
- `coverage_miss`：工具可执行，但目标没有记录。
- `assumption_violation`：算法假设不成立，例如主动约束不足。
- `low_quality`：存在输出但结果风险高。
- `conflict`：工具结果与其他证据明显冲突。
- `unavailable`：当前条件下无法恢复。

这些状态既帮助解决工具适配问题，也作为 Agent 的环境观察。

### 5.2 rDNS 适配

目标不是强行让 rDNS 覆盖所有地址，而是确认其有效场景：

1. 验证不同 resolver 下的真实 PTR 覆盖上限。
2. 使用规则、地名词典或 LLM 结构化解析已有 PTR。
3. 分析同前缀或同运营商 PTR 能否形成弱证据。
4. 输出直接证据、弱证据或不可用状态及质量等级。

### 5.3 主动定位适配

解决当前只有 3 个 probes、CBG 约束不足的问题：

1. 验证现有 2290 个 landmarks 和 traceroute 跳点能否构造有效约束。
2. 过滤位置、RTT、可达性和路径方向不可靠的约束。
3. 支持约束子集选择、不同 RTT 距离模型和求解器。
4. 输出约束数量、几何分布、交集面积和结果质量。

### 5.4 被动定位适配

将被动证据从单一 IPDB 扩展为：

- 可获得的 IPv6 IPDB。
- RIR/WHOIS 注册区域和组织文本。
- BGP Prefix-AS 与运营商归属。
- 严格按训练集隔离的同前缀、同 ASN 历史位置分布。

被动工具必须标明证据粒度与可靠性，不能把注册地伪装成精确实际位置。

### 5.5 工具效用进入条件

训练 Agent 前进行 Oracle 效用审计：

```text
Oracle误差 = 所有可用候选中与隐藏真值距离最小的误差
```

需要比较：

- 原始工具 Oracle。
- 适配后工具 Oracle。
- 成本约束 Oracle。
- 各工具对 ModuGeo 尾部样本的可修正比例。

只有适配后至少一种工具能够提供可靠互补候选，Agent 调度训练才具有实际意义。

## 六、多轮 Agent 环境

### 6.1 Agent 观测

Agent 可观察：

- 目标 IPv6 的匿名化或结构化前缀特征。
- ASN、运营商、WHOIS 和 BGP 等非真值属性。
- ModuGeo 候选、置信度与风险特征。
- 工具适用性、执行状态和质量特征。
- 已调用工具结果、冲突状态和剩余预算。

Agent 不可观察：

- `truth_region`、`truth_city` 和真实经纬度。
- 由测试集真值直接计算出的特征。
- 测试集近邻真值或其他数据泄漏信息。

### 6.2 Agent 动作

| 动作组 | 示例动作 | 目的 |
| --- | --- | --- |
| 适用性检查 | `inspect_tool_applicability(tool)` | 判断工具是否值得调用 |
| 工具调用 | `query_rdns`、`run_active_solver`、`query_passive_evidence` | 获取主动或被动证据 |
| 参数选择 | `select_landmark_subset`、`set_solver_strategy` | 调整工具执行方式 |
| 质量检查 | `inspect_result_quality(tool)` | 避免错误融合 |
| 候选比较 | `compare_candidates` | 比较 ModuGeo 与其他候选 |
| 输出 | `finalize(candidate, confidence)`、`abstain(granularity)` | 输出、降级或拒答 |

### 6.3 环境特性

- 多轮交互：动作执行后返回新观察，再进行下一步决策。
- 自动验证：隐藏真值用于计算地理误差和训练奖励。
- 预算约束：限制步骤、探针和高成本工具调用。
- 明确失败：工具无法执行时直接返回失败状态，不伪造输出。
- 严格隔离：检索或历史证据只允许访问训练划分。

## 七、SFT 冷启动

SFT 用于教会模型工具使用基础，而不是直接训练最终最优策略。

### 7.1 训练目标

1. 正确识别工具状态与适用条件。
2. 输出合法工具调用和参数。
3. 根据工具结果进行候选比较。
4. 在明显简单样本上及时停止。
5. 在工具不可用或结果低质量时避免错误融合。

### 7.2 轨迹生成

使用训练集隐藏真值，通过规则、束搜索和 Oracle 生成教师轨迹：

```text
观察 -> 适用性判断 -> 工具调用 -> 结果质量检查
     -> 继续取证/融合/停止 -> 最终答案
```

真值只用于评价教师轨迹，不得写入 Agent 输入。

轨迹应覆盖：

- ModuGeo 已正确，应立即停止的样本。
- 某个主动或被动工具能够修正 ModuGeo 的样本。
- 工具无覆盖或低质量，应跳过的样本。
- 多工具冲突，需要谨慎决策的样本。
- 没有可靠证据，应拒答或降低粒度的样本。

建议使用 Qwen 1.5B 至 7B 指令模型配合 LoRA/QLoRA。

## 八、GRPO 强化学习

GRPO 对同一目标采样多条 Agent 轨迹，根据隐藏真值、工具成本和行为质量进行组内相对优化。

### 8.1 训练流程

```text
对同一目标采样 G 条多轮轨迹
  -> 在定位环境中执行工具调用
  -> 计算每条轨迹的可验证奖励
  -> 组内归一化相对优势
  -> 更新 Agent 策略
```

### 8.2 奖励设计

```text
R = R_geo + R_improve + R_applicability + R_tail + R_granularity
    - R_cost - R_invalid - R_bad_fusion - R_unsupported
```

- `R_geo`：最终预测与隐藏真值的球面距离奖励。
- `R_improve`：相对 ModuGeo 的误差改善奖励。
- `R_applicability`：正确判断工具是否适用和结果是否可靠的奖励。
- `R_tail`：修正 ModuGeo 尾部错误的额外奖励。
- `R_granularity`：正确选择城市、省级或拒答的奖励。
- `R_cost`：无效、重复和高成本调用惩罚。
- `R_invalid`：非法动作与格式错误惩罚。
- `R_bad_fusion`：融合低质量工具结果造成退化的惩罚。
- `R_unsupported`：最终结论缺少证据支持的惩罚。

课程训练顺序：

1. 合法工具调用与停止。
2. 工具适用性和质量判断。
3. 单工具取证与纠错。
4. 多轮、多工具证据整合。
5. 未见前缀和尾部样本上的决策。

## 九、实验设计

### 9.1 工具适配实验

该组实验验证 Agent 环境是否成立：

- rDNS resolver、解析方式和证据等级对比。
- CBG 原始 probes、landmarks 扩充、质量过滤和求解器对比。
- 单一 IPDB 与多源被动证据对比。
- 工具适配前后的覆盖率、误差、质量和 Oracle 上界。

### 9.2 Agent 对比实验

- ModuGeo。
- 固定调用全部工具。
- 规则调度 Agent。
- 当前单步 Qwen 调度器。
- Prompt-only 多轮 Agent。
- SFT-only Agent。
- SFT + DPO Agent。
- SFT + GRPO Agent。
- Oracle 上界。

### 9.3 核心指标

工具环境指标：

- 原始覆盖率和有效覆盖率。
- 工具适用性判断准确率。
- 输出质量分类准确率。
- Oracle 相对 ModuGeo 的改善空间。

定位效果指标：

- Median、Mean、P90、P95 error。
- 相对 ModuGeo 的改善率和退化率。
- 尾部样本挽救率。
- 城市级和省级准确率。

Agent 能力指标：

- 有效工具调用率。
- 平均步数和调用成本。
- 无效工具调用率。
- 停止决策准确率。
- 非法动作率。
- 拒答后的 selective risk。

泛化指标：

- 未见 `/48`、`/56` 前缀。
- 未见 ASN 或运营商。
- 不同工具缺失和质量退化条件。

### 9.4 必做消融

- 去掉工具适用性观察。
- 使用原始工具与使用适配后工具对比。
- 去掉 SFT 冷启动，直接 GRPO。
- 去掉 GRPO，仅使用 SFT。
- 去掉相对 ModuGeo 的改善奖励。
- 去掉成本和错误融合惩罚。
- 单步调度与多轮 Agent 对比。
- 不允许拒答与允许拒答对比。

## 十、创新点

建议将论文创新点表述为：

1. **提出面向 IPv6 定位的可验证多轮 Agent 环境**，统一建模主动与被动工具调用、结果质量判断、候选融合和停止决策。
2. **提出工具适用性感知的 Agent 决策机制**，解决定位工具与目标数据集不匹配造成的无效调用和错误融合问题。
3. **提出无泄漏的 SFT 冷启动轨迹构造方法**，训练 Agent 掌握工具使用、证据读取和基本决策。
4. **提出面向 ModuGeo 尾部纠错的 GRPO 奖励机制**，联合优化定位改善、工具成本、适用性判断和可信拒答。

工具适配是第二个创新点和环境构建关键问题，但论文主线仍然是：

> **通过 SFT 与 GRPO 训练能够自适应使用主动、被动定位工具的 IPv6 地理位置推断 Agent。**

## 十一、实施顺序

### 阶段 A：工具环境可行性

1. 建立统一工具状态、失败原因和质量特征。
2. 完成 rDNS、主动定位和被动定位的适配实验。
3. 运行适配前后的 Oracle 工具效用审计。
4. 确认至少一种工具能够提供可靠互补候选。

### 阶段 B：多轮环境与 SFT

1. 删除当前 SFT 状态中的 `truth_region`、`truth_city`。
2. 将单步调度改造成多轮 Agent 环境。
3. 生成工具调用、质量判断、停止和拒答轨迹。
4. 使用 LoRA 完成 SFT。

### 阶段 C：GRPO

1. 接入多轨迹采样与环境执行。
2. 实现定位改善、适用性、成本和错误融合奖励。
3. 进行课程式 GRPO 训练。
4. 分析策略退化和奖励投机。

### 阶段 D：论文实验

1. 完成 Prompt、SFT、DPO、GRPO 和规则基线对比。
2. 完成工具环境、奖励和多轮机制消融。
3. 完成未见前缀与尾部错误分析。
4. 固化数据、配置、日志和可复现实验命令。

## 十二、风险边界

- Agent 无法凭空创造数据中不存在的定位证据。
- 如果适配后 Oracle 仍无法超过 ModuGeo，完整调度 Agent 缺少可学习收益，应收缩为工具适用性判断、风险控制和可信停止研究。
- rDNS 的结构性稀疏可能无法改善，但仍可用于训练 Agent 识别不可用场景。
- landmarks 不一定能够直接作为 CBG 探针，必须验证约束语义和 RTT 来源。
- WHOIS/BGP 与历史位置存在偏差和泄漏风险，必须标注证据粒度并严格隔离训练测试数据。
- “使用 GRPO”本身不构成创新，贡献必须来自多轮环境、工具适用性机制、轨迹构造、奖励设计和实证结果。
