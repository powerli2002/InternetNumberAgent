## 1. 研究对象概述

当前毕设围绕 **IPv6 地理位置推断** 展开，系统形态是一个带工具调用能力的 Agent 实验框架。系统不让 LLM 直接凭空预测经纬度，而是将已有定位方法封装为可复现工具，由 Agent 或调度器根据目标 IPv6、工具状态、候选位置、失败原因和预算约束进行决策。

当前已经实现的能力包括：

- 使用 ModuGeo/TrustGeo 预测作为基础定位器。
- 使用 rDNS/PTR hostname 作为语义定位证据。
- 使用 CBG/NCR/NCR-CBG 主动三角定位作为主动测距证据。
- 使用本地 IPDB backend 框架作为被动定位证据。
- 使用 WHOIS/BGP 作为注册与路由上下文证据。
- 使用 FusionTool 对多工具候选进行加权融合和冲突惩罚。
- 使用规则调度、Contextual Bandit、受限 Qwen 工具选择 baseline 和离线 reward policy 做调度对比。
- 构建 P0 阶段无泄漏、可回放、多轮 Agent 环境。
- 生成 SFT seed 和 GRPO prompts。
- 使用 Oracle 审计工具动作空间的理论收益上界。

当前尚未完成：

- 正式 SFT 训练。
- 正式 GRPO 训练。
- 训练后 Agent checkpoint。
- 基于新增 PostgreSQL 数据资产的统一训练数据集构造。
- 将增量 traceroute 与移动端 IP 定位 app 数据纳入 P0/P1 训练环境。

### 3.3 主动定位结果

当前 TrustGeo 数据中 probes 只有 3 个。CBG 主动定位在测试集上覆盖约 59.4%，但误差明显高于 ModuGeo。

可写入论文的事实：

- 当前主动定位的主要限制不是代码无法运行，而是约束来源不足和约束质量不足。
- 现有增量 traceroute 数据中有 1,696,766 条 probe 结果、18,655 个目标 IP、62 个源 IP，可作为后续扩充主动定位环境的数据来源。
- 增量 traceroute 的 stop reason 以 GAPLIMIT 为主，说明路径不完整或达到 gap-limit 的情况非常普遍。

### 3.4 被动 IPDB 结果

当前被动 IPDB 框架已经实现 multi backend，但在当前评测中覆盖率为 0%。

可写入论文的事实：

- 被动 IPDB 当前瓶颈是可用 IPv6 数据文件和后端资源，而不是接口框架。
- IP 信息库中已有 5,050,000 条 geo_info 和 130,045 条 ASN 记录，但其城市/区域字段质量与定位精度边界需要单独审计。
- 互联网号码资源融合库提供大量 WHOIS/RDAP/BGP/AS/ASN/组织上下文，可作为被动证据和解释证据。

| 100% | 929 | 61.169 km | 2030.776 km |

可写入论文的事实：

- 当前基础定位器存在长尾错误。
- 如果能够识别低风险样本，选择性输出有明显理论空间。
- 这不等同于已经训练出风险模型；它只是说明当前数据中存在风险分层信号。

## 6. 当前 SFT/GRPO 数据状态

当前已经生成的训练准备数据：

| 数据 | 数量 | 状态 |
| --- | ---: | --- |
| SFT seed | 650 | 已构造，无显式真值泄漏 |
| GRPO prompts | 650 | 已构造，无显式真值泄漏 |

当前 SFT seed 的特点：

- 只使用 train split。
- 教师轨迹由 Oracle 在训练集上生成。
- 模型输入不包含真实经纬度、真实城市或奖励。
- 所有轨迹均以 `finalize` 或 `abstain` 结束。
- 非 ModuGeo 教师轨迹较少，训练集中约 35 条。

当前限制：

- SFT seed 动作分布严重偏向直接使用 ModuGeo。
- 工具失败识别、质量判断、证据冲突、拒答和降级输出轨迹不足。
- GRPO prompt 已有，但还没有正式 rollout 训练和参数更新。

## 7. 可用于论文的主要阶段性结论

以下表述可以作为论文“阶段性发现”或“实验结果摘要”的基础：

1. 在当前 TrustGeo 适配数据上，ModuGeo 是唯一稳定有效的坐标级基线，测试集 Median 误差约 31.8 km，全量 P0 Median 误差约 30.2 km。
2. 当前 rDNS/PTR 在中国 IPv6 样本上的覆盖率极低，2 万级 PTR 查询命中率约 1.0%，在当前评测中未形成有效定位候选。
3. 当前 CBG 主动定位可在部分目标上运行，但由于 probe 数量少、约束质量不足，测试集 Median 误差约 678 km，直接融合会显著降低定位效果。
4. 当前被动 IPDB 框架已经存在，但缺少可用 IPv6 数据源，评测覆盖率为 0%。
5. 当前 P0 环境已经实现模型可见数据与私有真值分离，泄漏审计为 0，确定性回放通过，具备作为 SFT/GRPO 数据环境的基础。
6. 当前 Oracle 工具效用审计显示，非 ModuGeo 工具仅在 48/929 个目标上优于 ModuGeo，改善率为 5.17%，Oracle P90 与 ModuGeo P90 相同。
7. 当前基础定位器存在长尾错误，13.56% 的目标误差超过 100 km，10.01% 的目标误差超过 125 km。
8. 数据库中已经存在更大规模的增量 traceroute 数据和移动端 IP 定位 app 数据，它们尚未进入 P0 训练集，但具备构造下一阶段真实数据集的潜力。

## 8. 面向未来规划的可讨论问题

以下问题适合交给 GPT Pro 继续规划论文路线、实验设计和章节组织。

### 8.1 数据集构造问题

当前已有三类数据：

1. TrustGeo/ModuGeo benchmark：929 个目标、已有预测、已有 traceroute 和 landmarks。
2. 增量 traceroute 数据：约 169.7 万条 probe 结果、18,655 个目标、62 个源 IP。
3. 移动端 IP 定位 app 数据：93,885 条采集记录、92,423 条带经纬度、14,324 个不同 device_ipv6。

可讨论：

- 如何把移动端 GPS 位置和 traceroute 主动测量对齐成新的 IPv6 geolocation benchmark？
- 如何处理 GPS 来源质量差异，例如 GPS定位、WiFi定位、基站定位、缓存定位？
- 如何按设备、时间、前缀、ASN 做划分，避免同设备或同前缀泄漏？
- 如何定义训练集、验证集、测试集和 prefix-OOD 测试集？

### 8.2 工具适配问题

可讨论：

- 如何用 169.7 万条 probe 结果补足当前主动定位只有 3 个 probes 的问题？
- 如何从 traceroute stop reason 和 quality_score 中筛选可用主动约束？
- 如何将 IP 信息库、号码资源融合库中的 ASN/WHOIS/BGP/RDAP 信息变成被动证据？
- 如何区分“注册地证据”“路由归属证据”“真实使用位置证据”？

### 8.3 Agent 训练问题

当前 P0 已有 650 条 SFT seed 和 650 条 GRPO prompts，但动作分布不平衡。

可讨论：

- 如何扩展 SFT 数据，使工具失败诊断、质量判断、冲突处理、拒答和降级输出都有足够样本？
- 如何设计 GRPO 奖励，让 Agent 学会风险控制，而不是只追求坐标误差？
- 如何让 Agent 在工具缺失或低质量时输出可信拒答，而不是错误融合？
- 如何比较 Prompt-only、SFT-only、SFT+GRPO、规则、传统分类器和 Oracle？

### 8.4 论文贡献组织问题

可讨论的论文贡献方向：

- 构建一个无泄漏、可回放的 IPv6 geolocation Agent 环境。
- 系统评估 rDNS、主动定位、被动 IPDB 在真实中国 IPv6 数据上的有效性与失败原因。
- 使用 Oracle 审计量化工具动作空间上界，避免盲目训练 Agent。
- 将增量 traceroute 与移动端 GPS app 数据用于构造更大规模真实 IPv6 定位 benchmark。
- 将 Agent 目标从单纯提升全量坐标精度扩展到工具适用性判断、风险识别、选择性输出和可信拒答。

## 9. 写论文时需要避免的表述

当前结果不支持以下强表述：

- “LLM Agent 已经显著提升 IPv6 定位精度。”
- “GRPO 训练已经完成。”
- “rDNS 是当前数据集上的有效主力定位工具。”
- “CBG 主动定位在当前 TrustGeo 数据上优于 ModuGeo。”
- “被动 IPDB 已经提供可用 IPv6 城市级覆盖。”
- “当前 929 个目标足以代表整个互联网 IPv6 分布。”

当前结果支持以下谨慎表述：

- “当前实验揭示了 rDNS 稀疏、主动约束不足、被动 IPv6 数据源缺失等现实限制。”
- “当前系统适合继续围绕无泄漏数据构造、工具适用性、风险控制和选择性输出进行论文实验规划。”
