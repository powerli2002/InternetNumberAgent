# 《一种基于强化学习工具调度与多源证据融合的 IPv6 地址地理定位方法及系统》专利交底书撰写指导

## 1. 本指导文件的用途

本文档不是正式专利交底书正文，而是用于指导后续撰写交底书的技术组织思路。

本专利可以包含尚未完全实现的目标方案。撰写时应以“技术问题、技术方案、有益效果、实施方式”为主线，重点保护学习型调度机制与多源证据融合机制，而不是保护某一个具体 IP 定位工具。

## 2. 已确认的撰写目标

拟定题目：

```text
一种基于强化学习工具调度与多源证据融合的 IPv6 地址地理定位方法及系统
```

专利类型定位：

```text
方法 + 系统型专利
```

保护重点：

```text
1. 成本约束下的学习型工具调度机制。
2. 面向 IPv6 地址定位任务的多轮决策机制。
3. 主动探测预算规划与成本约束机制。
4. 多源定位证据融合、冲突检测与置信度校准机制。
5. 可审计的工具调用、证据链、成本与失败原因输出机制。
```

不作为保护重点：

```text
1. 某一个具体定位工具本身。
2. ModuGeo、rDNS、CBG、RIPE Atlas、scamper、WHOIS/BGP、IPDB 等具体工具算法。
3. 某一种固定数据源或固定探针平台。
```

这些工具在交底书中应作为“可替换的定位能力模块”或“实施例中的工具实例”出现，避免把权利要求限定到某一个具体工具。

## 3. 专利核心抽象

撰写时建议把系统抽象成以下闭环：

```text
目标 IPv6 地址
  -> 状态特征构造
  -> 学习型调度策略选择动作
  -> 调用一个或多个定位能力模块
  -> 更新观测状态、预算状态和证据状态
  -> 多源证据融合
  -> 判断是否停止或继续探测
  -> 输出位置、置信度、证据链和成本
```

其中，真正要突出的是：

```text
1. 状态如何表达。
2. 动作如何定义。
3. 成本敏感奖励或效用函数如何设计。
4. 多轮决策如何进行。
5. 主动探测预算如何约束。
6. 多源证据如何融合。
7. 何时停止并输出结果。
```

## 4. 建议突出的技术问题

背景技术中不要只写“IPv6 地址定位难”，而要写出具体技术矛盾：

```text
1. 单一定位工具覆盖率有限，不同工具适用样本不同。
2. IPv6 地址空间稀疏、前缀聚合明显，导致传统 IPv4 定位方法直接迁移效果不足。
3. 主动测量可以提高部分样本定位可靠性，但探针、时间和平台调用成本较高。
4. 多个工具可能产生冲突结果，简单平均会降低定位可信度。
5. 固定调用全部工具会造成不必要成本，固定规则又难以适配不同网络上下文。
6. 黑盒模型直接输出经纬度缺少证据链，难以审计和复现。
```

由此引出本发明要解决的问题：

```text
在 IPv6 地址地理定位任务中，如何根据目标地址上下文、已有定位证据、工具成本和主动探测预算，自适应选择定位工具，并对多源结果进行可信融合，从而在控制成本的同时提升定位准确性、覆盖率和可审计性。
```

## 5. 建议的发明点组织

### 5.1 发明点一：面向 IPv6 定位的学习型调度状态建模

状态特征建议写成可扩展集合，而不是绑定当前代码字段。

可包括：

```text
1. 地址结构特征：IPv6 前缀长度、前缀聚合层级、目标地址所属地址块。
2. 网络归属特征：ASN、运营商、组织、路由前缀、注册区域。
3. 初始定位特征：基础定位结果、基础置信度、预测粒度。
4. 语义证据特征：rDNS 是否存在、主机名中是否包含地理语义、语义命中强度。
5. 主动测量特征：可用探针数量、地标数量、RTT 约束数量、探针地域分布。
6. 证据冲突特征：不同工具预测距离、区域一致性、置信度分歧。
7. 成本状态特征：已调用工具数量、已消耗探针预算、累计时间、剩余预算。
8. 历史决策特征：上一轮动作、上一轮新增证据、当前轮次。
```

写法建议：

```text
不要写成“必须包含以上全部特征”，而应写成“至少包括其中一种或多种”。
```

这样有利于扩大保护范围。

### 5.2 发明点二：工具调用动作空间

动作空间应抽象为定位能力动作，而不是具体工具名。

建议动作包括：

```text
1. 停止输出动作。
2. 调用基础定位能力动作。
3. 调用语义解析定位能力动作。
4. 调用主动测距定位能力动作。
5. 调用被动数据库查询定位能力动作。
6. 调用注册信息上下文补充动作。
7. 调用多源融合动作。
8. 调整主动探测预算动作。
9. 选择探针集合动作。
10. 继续下一轮决策动作。
```

实施例中可以说明：

```text
基础定位能力可以由前缀模型、已有定位模型或机器学习模型实现；
语义解析定位能力可以由 rDNS 解析实现；
主动测距定位能力可以由 CBG、三角定位、RIPE Atlas 或 scamper 实现；
注册信息上下文可以由 WHOIS、BGP、RDAP 或 ASN 数据实现。
```

注意：这些只是实施方式，不是保护边界。

### 5.3 发明点三：成本敏感奖励函数或效用函数

奖励函数或效用函数是本专利的重要创新点，应写得比较完整。当前项目更适合先采用离线奖励优化、上下文 Bandit 或其他轻量策略学习方法；PPO、GRPO 等深度强化学习方法不宜作为当前工程主实施例。

建议表达为：

```text
R = AccuracyReward
    + CoverageReward
    + ConfidenceCalibrationReward
    - ToolCostPenalty
    - ProbeCostPenalty
    - TimeCostPenalty
    - ConflictPenalty
    - InvalidActionPenalty
```

或写成更数学化的形式：

```text
R_t = - α · E_t
      - β · C_tool
      - γ · C_probe
      - δ · C_time
      - η · D_conflict
      + μ · I_coverage
      + ν · Q_calibration
```

其中：

```text
E_t 表示定位误差；
C_tool 表示工具调用成本；
C_probe 表示主动探测成本；
C_time 表示时间成本；
D_conflict 表示多源结果冲突度；
I_coverage 表示是否产生有效定位结果；
Q_calibration 表示置信度与真实误差的一致性。
```

如果训练阶段可以使用真值，则写：

```text
训练阶段基于带真值样本计算奖励；推断阶段不使用真值，仅使用当前可观测状态进行动作选择。
```

### 5.4 发明点四：多轮工具调度与主动探测预算规划

这是区别于单步 Contextual Bandit 的目标方向。撰写时可以把多轮预算规划作为专利保护范围，但当前工程实现应优先落在可验证的离线奖励策略或上下文 Bandit 上。

建议写成：

```text
系统将一次 IPv6 地址定位过程建模为多轮序贯决策过程。每一轮根据当前状态选择是否调用新的定位能力、是否执行主动探测、是否增加探针数量、是否停止输出。
```

主动探测预算可以包括：

```text
1. 单个目标地址最大探针数。
2. 单批任务最大主动探测目标数。
3. 单个探针平台最大调用次数。
4. 最大等待时间。
5. 最大测量失败重试次数。
6. 按运营商、省份、前缀或置信度分层配置预算。
```

策略可学习：

```text
1. 对高置信样本提前停止。
2. 对低置信且存在足够探针资源的样本触发主动测距。
3. 对证据冲突大的样本调用补充证据模块。
4. 对预算不足或预期收益低的样本停止并输出低置信结果。
```

推荐优先写成离线奖励优化、上下文 Bandit 或轻量序贯决策方法：

```text
策略根据状态向量估计不同工具动作的期望收益，并在定位误差、工具成本、探针成本和证据冲突之间进行权衡；策略参数可由离线轨迹、历史评测结果或上下文 Bandit 训练得到。
```

PPO、GRPO 或 Actor-Critic 可作为远期可选扩展描述，但应明确其适用前提：

```text
1. 已积累足够多轮工具调用轨迹。
2. 奖励函数稳定且可验证。
3. 主动探测动作具备可控仿真环境或安全预算约束。
4. 相比 Bandit 或离线奖励策略能带来可验证收益。
```

不建议在交底书主实施例中承诺“已采用 PPO/GRPO 实现”。

### 5.5 发明点五：多源证据融合与冲突处理

融合机制应和 RL 调度并列作为核心创新点。

建议写成：

```text
系统将不同定位能力输出统一转换为证据对象，每个证据对象包含位置、粒度、置信度、成本、来源、时间戳、失败原因和辅助解释信息。
```

融合步骤可包括：

```text
1. 过滤不可用证据。
2. 按证据粒度分层处理，例如国家级、省级、城市级、坐标级。
3. 根据工具可靠性、当前状态相关性、历史表现和置信度计算动态权重。
4. 对坐标级证据进行加权融合。
5. 对区域级证据进行一致性约束。
6. 计算工具间地理冲突距离。
7. 根据冲突度降低最终置信度或触发下一轮调度。
8. 输出最终位置、置信度、冲突列表和证据链。
```

可以强调：

```text
融合权重不是固定常数，而是可由学习型调度策略、历史评测结果或当前上下文动态调整。
```

### 5.6 发明点六：可审计输出

可审计性可以作为有益效果，也可以写成系统模块。

输出建议包括：

```text
1. 最终经纬度或区域结果。
2. 定位粒度。
3. 最终置信度。
4. 被调用工具列表。
5. 被跳过工具及跳过原因。
6. 每个工具的输出、成本和失败原因。
7. 多源证据冲突度。
8. 学习型调度策略选择的动作序列。
9. 主动探测预算消耗情况。
10. 停止决策原因。
```

该部分有助于区别“黑盒模型直接预测经纬度”的方案。

## 6. 建议的交底书章节结构

正式交底书可按以下结构撰写。

### 6.1 技术领域

建议写：

```text
本发明涉及互联网测量、IPv6 地址地理定位、学习型决策调度、多源信息融合和网络空间测绘技术领域，尤其涉及一种基于强化学习工具调度与多源证据融合的 IPv6 地址地理定位方法及系统。
```

### 6.2 背景技术

重点写：

```text
1. IPv6 地址定位相比 IPv4 更困难。
2. 现有单一工具覆盖率和适用场景有限。
3. 主动探测成本高，不适合固定调用。
4. 多源结果存在冲突，缺少统一融合和置信度校准。
5. 现有方法难以根据样本上下文动态选择工具。
```

### 6.3 发明目的

建议写成：

```text
本发明旨在提供一种能够根据 IPv6 地址上下文、已有证据和成本预算自适应选择定位能力，并对多源定位结果进行融合、冲突处理和置信度校准的方法及系统。
```

### 6.4 技术方案

这是核心部分。建议按照以下顺序写：

```text
1. 输入目标 IPv6 地址及可选上下文数据。
2. 构造状态向量。
3. 通过学习型调度策略选择工具调用动作。
4. 执行动作并获得工具证据。
5. 更新状态、证据集合和预算状态。
6. 进行多源证据融合与冲突检测。
7. 判断是否停止；若不停止，则进入下一轮决策。
8. 输出定位结果、置信度、证据链和成本。
```

系统部分可以写成以下模块：

```text
1. 输入与预处理模块。
2. 状态特征构造模块。
3. 定位能力注册与调用模块。
4. 学习型调度模块。
5. 主动探测预算规划模块。
6. 多源证据融合模块。
7. 置信度校准模块。
8. 证据链与审计输出模块。
9. 策略训练与评测模块。
```

### 6.5 有益效果

建议突出：

```text
1. 相比固定调用全部工具，降低平均工具调用成本和主动探测成本。
2. 相比单一定位工具，提高复杂样本或低置信样本的定位可靠性。
3. 通过冲突惩罚和置信度校准，降低错误高置信输出的风险。
4. 通过多轮决策，使主动探测资源集中用于预期收益较高的目标。
5. 通过证据链输出，提高定位结果的可解释性、可审计性和可复现性。
```

## 7. 权利要求撰写思路提示

虽然本文件不写正式权利要求，但后续撰写时建议围绕以下保护层级展开。

### 7.1 独立方法权利要求

核心步骤建议包括：

```text
1. 获取目标 IPv6 地址及上下文信息。
2. 构造包含网络归属、已有证据、成本预算和历史动作的状态特征。
3. 将定位过程建模为成本约束下的序贯决策过程。
4. 由学习型调度策略选择定位能力调用动作。
5. 执行所选动作并获得定位证据。
6. 对定位证据进行多源融合和冲突处理。
7. 根据融合结果和预算状态判断停止或继续。
8. 输出定位结果、置信度、证据链和成本信息。
```

### 7.2 独立系统权利要求

系统模块建议包括：

```text
1. 状态构造模块。
2. 学习型调度模块。
3. 定位能力调用模块。
4. 主动探测预算模块。
5. 多源证据融合模块。
6. 置信度校准模块。
7. 证据链输出模块。
```

### 7.3 从属权利要求可覆盖的点

可进一步保护：

```text
1. 状态特征的具体组成。
2. 动作空间的具体类型。
3. 奖励函数的成本、误差、冲突和覆盖项。
4. 主动探测预算的限制方式。
5. 工具冲突距离的计算方式。
6. 动态融合权重的计算方式。
7. 置信度校准方式。
8. 低置信、冲突大、预算不足时的停止策略。
9. 训练阶段使用真值、推断阶段不使用真值的机制。
10. 证据链记录字段。
```

## 8. 技术实现目标清单

由于该专利可以包含尚未实现的目标，后续实现可按以下目标推进。

### 8.1 学习型调度目标

```text
1. 将单个 IPv6 地址定位过程建模为多步 MDP。
2. 实现策略网络，输入状态向量，输出工具动作概率。
3. 优先支持离线奖励优化、上下文 Bandit 或轻量序贯策略训练。
4. 支持离线轨迹生成，用已有定位样本构造训练数据。
5. 支持成本敏感奖励函数。
6. 支持策略在不同预算约束下切换。
7. 在具备足够多轮轨迹和稳定仿真环境后，再评估 PPO、GRPO 或 Actor-Critic。
```

### 8.2 主动探测预算目标

```text
1. 建立目标级、批次级、平台级预算。
2. 根据当前置信度和预期收益决定是否探测。
3. 根据探针位置、网络类型和历史质量选择探针集合。
4. 对探测失败、超时和重复探测进行惩罚。
5. 将预算消耗写入状态特征和证据链。
```

### 8.3 多源融合目标

```text
1. 统一不同定位工具的证据对象格式。
2. 支持坐标级、城市级、省级和国家级分层融合。
3. 支持根据历史表现动态调整工具权重。
4. 支持工具冲突触发继续调度。
5. 支持最终置信度校准。
```

### 8.4 可审计输出目标

```text
1. 记录动作序列。
2. 记录每个动作的输入、输出、成本和失败原因。
3. 记录融合使用的证据和冲突距离。
4. 记录停止原因。
5. 输出可用于复现实验的 JSON 或 JSONL 轨迹。
```

## 9. 撰写时应避免的问题

### 9.1 避免把工具写成核心保护对象

不建议写：

```text
本发明通过 ModuGeo、rDNS 和 CBG 实现 IPv6 定位。
```

建议写：

```text
本发明通过学习型调度策略在多个可替换定位能力模块之间进行调度，所述定位能力模块可以包括基础定位模块、语义解析模块、主动测距模块、被动数据库模块和注册信息上下文模块。
```

### 9.2 避免只写固定规则

不建议把方案写成：

```text
如果置信度低就调用主动探测。
```

应写成：

```text
学习型调度策略根据置信度、预算、证据冲突、探针可用性和历史动作综合选择是否调用主动探测；固定规则仅作为一种退化实施方式。
```

### 9.3 避免承诺不可验证效果

不要写绝对化表述：

```text
必然提高所有 IPv6 地址定位精度。
```

建议写：

```text
在相同或受控成本条件下，提高部分低置信样本、证据冲突样本或主动测量可达样本的定位可靠性。
```

### 9.4 避免把 RL 写得过窄

不要把当前工程不适合的复杂算法写成主实现：

```text
使用 PPO 算法进行工具选择。
```

建议写：

```text
学习型调度策略优先采用离线奖励优化、上下文 Bandit 或其他可验证的轻量策略优化方法实现；在具有足够多轮轨迹、稳定奖励和安全仿真环境时，也可扩展为 PPO、GRPO 或 Actor-Critic。
```

PPO 或 GRPO 只能作为远期可选扩展，不宜作为当前项目的优选实施例。
