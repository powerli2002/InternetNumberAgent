# Agentic IPv6 Geolocation 系统实现过程

## 1. 实现目标

本次实现遵照 `Agentic_IPv6_Geolocation_Plan.md`，完成一个可复现的“基于 Agent 调度的 IPv6 地理位置推断系统”。系统不使用 LLM 直接预测经纬度，而是围绕确定性工具、规则/学习型调度、融合与评测闭环组织。

核心目标包括：

- 复用 `/home/lzj/TrustGeo` 中已有数据与模型输出。
- 将 TrustGeo 数据适配为统一 CSV 输入契约。
- 实现 `ModuGeoTool`、`RDnsGeoTool`、`ActiveTriangulationTool`、`WhoisBgpContextTool`。
- 复用 `GraduatePaper/cbgtool` 的 CBG 主动三角定位实现，NCRGeo 与 NCR-CBG 混合方法作为配置级备选。
- 实现 `FusionTool`、`RuleAgentScheduler`、`ContextualBanditScheduler`。
- 实现批量预测、数据校验、单工具评测、融合评测、调度评测、分组指标、成本-精度分析、CDF 数据输出和 Streamlit 可视化界面。
- 使用 `uv` 在当前目录创建环境并完成运行验证。

## 5. 工具实现

### ModuGeoTool

`ModuGeoTool` 优先复用 `data/trustgeo_processed/modugeo_predictions.csv` 中的 TrustGeo `pfxgeo_v11` 预测。若外部预测缺失，则回退到可解释的多尺度前缀、ASN/运营商语义质心、last-hop landmark 基线。外部预测置信度不使用 `error_km` 反推，避免把真实误差泄漏进推断流程。

### RDnsGeoTool

`RDnsGeoTool` 从 hostname token 中匹配城市别名、拼音缩写、机场码等。默认词典位于 `configs/rdns_lexicon.csv`，也保留内置基础词典。若无 hostname 或未命中地理词，直接返回 `unavailable`。新增 `RDnsCollector` 后，工具可在配置允许时通过系统 resolver 采集 rDNS，并写入可复用缓存；默认仍保持离线，不主动访问外部网络。

### ActiveTriangulationTool

`ActiveTriangulationTool` 是当前主动测距定位入口，默认配置为：

```json
{
  "algorithm": "cbg",
  "cbgtool_root": "cbgtool",
  "min_constraints": 3,
  "delta": 0.398,
  "sort_circles": 0
}
```

默认 CBG 流程复用 `GraduatePaper/cbgtool/scripts/utils/helpers.py` 的 `select_best_guess_centroid`，输入为多个探针位置和探针到目标的 RTT。RTT 提取优先使用到达目标 IP 的 RTT；若 traceroute 未到达目标，则使用该探针最后可见 hop 的 RTT。有效约束少于 3 个时直接返回 `unavailable`。

NCRGeo 与 NCR-CBG 已作为备选算法适配到同一工具中，可通过 `active_triangulation.algorithm` 配置为 `ncr` 或 `ncr-cbg`。这两个备选方法依赖 SciPy/ujson；默认环境不强制安装，依赖缺失时工具会返回明确失败原因或回退到原始 CBG，并在证据字段记录回退原因。

主动约束来源扩展为三类：已有 trace、`ScamperTraceProvider` 缓存/实时探测、`RipeAtlasProvider` measurement 结果。真实主动探测由 `active_probe.allow_live_measurements` 控制，RIPE Atlas 凭据只从环境变量读取。RIPE Atlas API 使用约束整理在 `skills/ripe-atlas/SKILL.md`。

### PassiveIpDbGeoTool

`PassiveIpDbGeoTool` 使用本地 CSV 形式的 IP 地理位置库，支持按单 IP 或最长前缀命中，输出低成本候选位置、数据库版本、命中粒度和置信度。该工具默认关闭，不把数据库结果当作真值，只作为融合证据。

### WhoisBgpContextTool

该工具只输出 ASN、组织、BGP 前缀、注册省市等上下文证据，不作为强定位器。

## 6. 抽象与扩展

后端方法抽象位于 `src/agentic_ipv6_geo/tools/registry.py`：

- `MethodSpec` 记录方法 ID、名称、类别、描述、配置键、成本级别和证据类型。
- `build_methods()` 负责按配置构造并拟合工具。
- 前端、批量评测和调度器都通过注册表构造方法，后续新增定位算法时优先扩展注册表。

前端与报告显示名称位于 `src/agentic_ipv6_geo/common/catalog.py`。后端结构化输出继续保留稳定实验 ID，Streamlit 和 Markdown 报告显示中文友好名称，避免直接把 JSON 或内部 ID 暴露给用户。

## 7. 融合与调度

### FusionTool

融合策略为置信度与工具可靠性加权：

```text
位置 = 坐标级工具结果按 confidence * tool_reliability 加权
置信度 = 工具平均置信度 - 地理冲突惩罚 + 多证据奖励
```

工具间坐标距离会写入 `evidence.conflicts`，用于分析冲突样本。

### RuleAgentScheduler

规则式调度流程：

```text
1. 调用 ModuGeoTool。
2. 调用 WhoisBgpContextTool 获取上下文。
3. 若 rDNS 存在，调用 RDnsGeoTool。
4. 若 ModuGeo 置信度低，调用 ActiveTriangulationTool。
5. 调用 FusionTool。
6. 达到阈值则停止，否则输出低置信结果并记录原因。
```

### ContextualBanditScheduler

实现了轻量离线上下文 bandit：

- 训练阶段在训练集上模拟 `stop`、`rdns`、`active`、`all` 四类动作。
- 奖励函数为 `R = - Error_km - λ1 * ToolCost - λ2 * ProbeCost`。
- 上下文特征包括 ModuGeo 置信度桶、rDNS 是否可用、主动三角定位约束数量桶、运营商字段。
- 推断阶段只使用可观测上下文选择动作，不读取真实坐标。

### QwenToolUseScheduler

新增 Qwen3.5 baseline 调度器。该调度器只允许模型在 `stop`、`rdns`、`active`、`passive`、`all` 中选择工具动作，不允许模型直接输出经纬度。默认配置下 Qwen 调用关闭，缺少 `QWEN_API_KEY` 或 `QWEN_BASE_URL` 时会退化为 `stop` 并在证据中记录原因。

### OfflineRewardPolicyScheduler

新增离线奖励 policy。训练阶段枚举工具动作，使用训练集真值计算奖励；推断阶段按上下文选择平均奖励最高的动作。奖励项包括误差、工具成本、探针成本、冲突惩罚、覆盖奖励和非法动作惩罚。该策略为后续 SFT/GRPO/PPO 等 RL 优化提供可复现实验基线。

## 10. Streamlit 可视化界面

新增 `src/agentic_ipv6_geo/ui/dashboard.py` 和启动命令 `ipv6geo-dashboard`。界面包含四个页面：

```text
总览：使用横向图展示目标、trace、探针、metadata、rDNS、landmark、ModuGeo 预测覆盖情况，并展示方法目录和 TrustGeo 适配说明。
自动定位：选择或输入 IPv6，点击“开始自动定位”，系统按规则调度或 Bandit 调度自行选择工具，输出坐标、置信度、成本、误差、调度决策过程和证据摘要。
训练与评测：点击按钮运行完整 Evaluator，展示 summary、误差对比图、成本-精度前沿和历史评测结果。
数据与输出：预览目标样本、列出输出文件，并直接查看 Markdown 实验报告。
```

自动定位按钮的内部流程：

```text
1. 加载配置和统一数据。
2. 划分训练/测试集。
3. 通过统一方法注册表构造 ModuGeo、rDNS、主动三角定位、WHOIS/BGP 和融合器。
4. fit ModuGeo 基线与 Bandit 策略。
5. 根据用户选择运行 RuleAgentScheduler 或 ContextualBanditScheduler。
6. 调度器自动决定是否调用 rDNS、主动三角定位和 Fusion。
7. 页面以类似 LangSmith trace 的节点流展示调用/跳过原因、节点状态和最终结果。
```

当前前端不直接展示 JSON；证据链会被整理为指标卡、表格、节点流和图表。总览与评测页使用横向 Altair 图，避免长实验名造成横坐标竖排不可读。
